# Build SmartBroker's Amharic dictation around swappable engines

> **Update, 8 October 2026 — the mobile model *is* on Hugging Face.** This report's statement that the offline model was not downloadable is wrong. The official repo [addisai/addis-scribe-streaming](https://huggingface.co/addisai/addis-scribe-streaming/tree/main/mobile) has a `mobile/` folder (uploaded 5 October 2026, not described in its README) with two quantized builds of Addis Scribe Streaming: `addis-scribe-rnnt-q5_k.gguf` (499 MB) and `addis-scribe-rnnt-q8_0.gguf` (720 MB).
> - **Licence:** OpenMDW-1.1, which allows free commercial use and redistribution if the licence and notices are kept, with no limits on outputs. Shipping it in SmartBroker is allowed.
> - **Runtime:** NVIDIA [NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp) (Apache-2.0, ggml-based), with a C API for batch (`nemo_speech_asr_recognize_f32`) and streaming (`nemo_speech_asr_stream_push_f32` / `_next`) recognition. Its build docs cover Linux, macOS, Windows and containers only; **Android is not documented**, so it would need a custom NDK build.
> - **Maturity:** the export report marks the files `exported-unqualified` and lists Amharic WER/CER after quantization, Android NDK compatibility, phone latency/RAM, battery and microphone handling as **unverified**.
>
> **Effect on the plan:** Phase 0 adds a spike to build NeMo-Speech.cpp for Android arm64 and run the q5_k model on a real phone (speed, RAM, accuracy against the cloud and Shook Tiny). If it passes, it becomes the default on-device engine (via a JNI or Dart FFI wrapper), with Shook Tiny kept as the lightweight fallback for low-RAM phones.

> **Spike, 20 October 2026 (in progress).** First results with the official `addis-scribe-rnnt-q5_k.gguf`:
> - **File and settings:** the download matches the export report's SHA-256 (`31aceccf…`). The model needs the language prompt `am-ET`; with `am` the runtime returns no text. Output has no punctuation, as the model card says. The runtime revision used for the export (`b809bbb`) and current main (`caa3f47`) give identical transcripts. On the test clip, streaming mode was more accurate than one offline pass, so the app should use streaming even for recorded notes.
> - **Android build:** NeMo-Speech.cpp builds for Android without source changes (arm64-v8a and x86_64, static libc++, 16 KB pages as Google Play requires, about 5 MB of native code; see `tool/scribe/build_android.sh`). The libraries must link `liblog`. It runs on the Android 17 emulator.
> - **Speed on two cores of an i5-13420H (Linux VM):** an 11 s clip takes 4.6 s offline (2.4× real time). Streaming takes 0.18 s on average per 0.32 s chunk, so it keeps up with live speech. Peak memory is about 1.3 GB, and the first run spends 8–10 s warming up, so the app must preload the model.
> - **English words come out in Ethiopic script:** the English JFK test clip was transcribed phonetically ("…ዩር ካንትሪ ከንዱ ፍዩ…"). Loanwords in broker notes will need fixing in the AI summary step.
> - **Pending:** speed and memory on a phone, and accuracy on SmartBroker-style voice notes (`tool/scribe/eval_notes.py`, `tool/emu_bridge.bat` → `scribe phone`).


Addis AI's offline Amharic transcriber cannot be integrated yet because it has not been released. As of 8 October 2026 it exists only as a 52-second founder demo, posted on Telegram on 5 October, of **"Addis Scribe running fully offline on-device"** with first text in about 0.3 s, plus a promise that quantized "Addis Scribe mobile models" will arrive "soon," exclusively on a third-party Model Hub. Nothing has been said about its format, size, licence, platform or accuracy, and there is no mobile SDK. What Addis AI does ship is a young cloud platform. Its **Scribe speech-to-text API** handles Amharic only, accepts notes up to 180 s, costs 3.5 ETB per 1,000 transcript characters and runs one job per account at a time. It has Node and Python SDKs but none for Dart, and its docs tell mobile apps to call it through their own backend. Accuracy beats the company's rivals on its own benchmark but falls far short of its marketing: the homepage advertises "3% WER," while Addis AI's own open-sourced Scribe Streaming model measures **19.8–28.4% WER**. That is in line with the best open research models and ahead of Google Chirp 3 on spontaneous speech. Its standard terms also let it **train on the audio customers send**, which is a real problem for notes full of client names, phone numbers and prices. SmartBroker should integrate Addis AI without waiting for the offline release. The plan is to record every note locally and transcribe it through a pluggable engine. On-device transcription would use Addis AI's own Apache-2.0 **Shook Tiny** model (a 37.8M-parameter Whisper-tiny fine-tune), provided it passes a test on real broker notes. Addis Scribe cloud would be a consented opt-in through a backend proxy, and the official mobile model can be swapped in once its licence and format are public. I estimate three to four weeks of work for one Flutter developer who knows the codebase.

## Addis AI's offline transcriber is a three-day-old demo, not a download

Addis AI describes itself as "voice-first AI infrastructure for African languages," currently Amharic and Afaan Oromo ([Hugging Face: addisai](https://huggingface.co/addisai)). It operates from **Orpund, Switzerland and Ethiopia**, with Biniyam Daniel as co-founder and CEO ([addisassistant.com](https://addisassistant.com/); [biniyamdaniel.com](https://www.biniyamdaniel.com/)). It lists NVIDIA Inception and Google for Startups among its backers but discloses no funding ([addisassistant.com](https://addisassistant.com/)), and its consumer voice-and-chat app has **100K+ Android downloads** ([Google Play](https://play.google.com/store/apps/details?id=com.danob.addisai.addis_assistnat)). Hasab AI and the iOS "Amharic TTS" app come from different companies and should not be confused with it ([Shega](https://shega.co/news/can-hasab-ai-launch-with-97-accuracy-be-a-turning-point-for-ethiopian-speech-technology); [App Store: Amharic TTS](https://apps.apple.com/us/app/amharic-tts/id6753888344)).

Everything known about the offline transcriber comes from three Telegram posts. On 5 October the CEO posted a demo of Addis Scribe running "fully offline on-device," with no Wi-Fi or mobile data and first text in about 0.3 s. He added that small open-source edge models will be a bigger focus ([t.me/b1n1yamBuilds/283](https://t.me/b1n1yamBuilds/283?embed=1)), and the official channel forwarded the post ([t.me/addisassistantai/228](https://t.me/addisassistantai/228?embed=1)). Forty-three minutes later he wrote that **"quantized versions of Addis Scribe mobile models"** would be released soon, **exclusively on ScholarXIV's Model Hub** ([t.me/b1n1yamBuilds/284](https://t.me/b1n1yamBuilds/284?embed=1)). ScholarXIV is an open-source arXiv reading app by the developer dagmawibabi ([GitHub: ScholArxiv](https://github.com/dagmawibabi/ScholArxiv)), and its channel showed no Model Hub or Addis model post when checked ([t.me/s/scholarxiv](https://t.me/s/scholarxiv)). The same developer publishes a third-party wrapper for Addis AI's STT API ([claudemarket.ai](https://claudemarket.ai/skills/dagmawibabi/addis-assistant-stt)), which points to a close partnership rather than an established distribution platform. The posts show no year. 2026 is inferred because the same-day PyPI SDK release is dated 5 October 2026 ([PyPI addisai](https://pypi.org/project/addisai/)). Neither app-store listing nor the developer docs mention offline transcription ([App Store](https://apps.apple.com/us/app/addis-ai/id6748835704); [docs: Speech-to-Text](https://docs.addisassistant.com/docs/capabilities/speech-to-text)). The device, platform, model size, file format, quantization level, minimum hardware, language coverage, accuracy, licence and release date are all **undisclosed**, and no press has covered it yet.

Addis AI has not said which model powers the demo, but two of its published models are plausible ancestors. On the same day, it open-sourced **Addis Scribe Streaming**, a 0.6B-parameter cache-aware FastConformer (hybrid RNNT+CTC) fine-tuned from NVIDIA's Nemotron 3.5 ASR Streaming 0.6B. It was trained on "5,000+ hours" of Amharic and is billed as "built for live and edge inference" ([t.me/addisassistantai/224](https://t.me/addisassistantai/224?embed=1)). The official repo ships only a `.nemo` checkpoint that needs NeMo with CUDA, benchmarked on an A100, under the **OpenMDW-1.1** licence ([HF: addisai/addis-scribe-streaming](https://huggingface.co/addisai/addis-scribe-streaming)). A mirror whose link to Addis AI is unexplained adds a **720 MB Q8_0 GGUF** ([HF: buctl/addis-scribe-streaming](https://huggingface.co/buctl/addis-scribe-streaming)). The other candidate is **Shook Tiny Amharic 600hr**, which Addis AI's open-source page positions for "on-device and low-latency use" ([addisassistant.com/open-source](https://addisassistant.com/open-source)). The talk of "small" models and the 0.3 s latency suggest something lighter than the 720 MB checkpoint, but that is inference. Whatever ships will be quantized, and its accuracy cannot be assumed to match the server model's.

## Cloud Scribe is the only Addis AI transcriber SmartBroker can use today

The developer platform includes an Amharic LLM (Addis-፩-አሌፍ, 128k context), Addis Voices 2 text-to-speech, translation, a beta realtime voice WebSocket and speech-to-text. Enterprise on-prem and VPC deployment is sold separately ([addisassistant.com](https://addisassistant.com/); [addisai.ch](https://www.addisai.ch/)).

Speech-to-text comes in two generations. The legacy **STT v2** endpoint (`POST /api/v2/stt`) caps files at **60 s and 10 MB**. The newer **Scribe** endpoint (`POST /api/v1/scribe/transcribe?backend=standard|turbo&request_id=…`) accepts WAV, MP3, M4A, WebM, OGG or FLAC up to **25 MB and 180 s**. It can stream partial results, its Turbo backend is roughly 3× faster at the same price, and a live WebSocket mode takes 16 kHz mono PCM16 after a one-use 60-second ticket ([docs: Speech-to-Text](https://docs.addisassistant.com/docs/capabilities/speech-to-text)). Scribe "currently recognizes only Amharic" and allows **one transcription per wallet at a time**, returning HTTP 429 otherwise. Completed results stay recoverable by request ID for 24 hours. Paid uploads are not retried automatically, so clients must save the request ID before sending audio ([docs: Speech-to-Text](https://docs.addisassistant.com/docs/capabilities/speech-to-text)). The 180-second cap matches SmartBroker's three-minute maximum exactly, so the app should stop recording a few seconds early.

Authentication is a secret `x-api-key` (`sk_…`) sent to `https://api.addisassistant.com` ([Quick Start](https://docs.addisassistant.com/docs/get-started/quickstart)). The only official SDKs are **Node.js and Python 0.4.0 (MIT)**. There is **no Dart, Flutter, Android or iOS SDK**. The mobile guide warns that "Mobile applications (APKs/IPAs) can be decompiled" and prescribes routing calls from the app through your own backend to Addis AI ([Docs: SDKs](https://docs.addisassistant.com/docs/get-started/sdks); [Docs: Mobile](https://docs.addisassistant.com/docs/integration/mobile)). The Terms also forbid embedding secret keys in client apps ([Terms](https://addisassistant.com/terms)).

The platform is young and changing fast. The Python SDK went from 0.1.0 to 0.4.0 between 15 July and 5 October 2026 ([PyPI addisai](https://pypi.org/project/addisai/)). When read on 8 October, the docs' status page still covered only 3–9 August, and the announcements page had a single entry ([Docs: Status](https://docs.addisassistant.com/docs/platform/status); [Docs: Announcements](https://docs.addisassistant.com/docs/announcements)). Language lists disagree as well: the SDK README says STT accepts six languages, while the docs say Scribe is Amharic-only ([PyPI addisai](https://pypi.org/project/addisai/)). A thin backend that pins the REST contract protects the app from these changes.

Billing comes out of a prepaid wallet **in Ethiopian birr**. Scribe costs **3.5 ETB per 1,000 characters of final transcript**, counted in UTF-16 units. Standard and Turbo cost the same, and audio duration, silence and partial results are not billed ([docs: Speech-to-Text](https://docs.addisassistant.com/docs/capabilities/speech-to-text); [Docs: Pricing](https://docs.addisassistant.com/docs/platform/pricing)). The homepage equates this to $0.022 per 1,000 characters, or **about ETB 1.40 per minute of speech** ([addisassistant.com](https://addisassistant.com/)). A comparison page advertises $3.17 of free signup credit with no card required ([Addis AI vs Azure](https://addisassistant.com/compare/microsoft)). The Free/Sandbox tier allows 60 requests per minute, 1,000 per day and 3 concurrent requests, and Pro raises that to 500 per minute and 50 concurrent ([Docs: Rate Limits](https://docs.addisassistant.com/docs/platform/limits)). Purchases are non-refundable. The only payment processors named are CanyoPay and card processors, and Telebirr or Chapa support is unconfirmed ([Terms](https://addisassistant.com/terms); [Privacy Policy](https://addisassistant.com/privacy)).

My estimate, assuming 400–800 transcript characters per spoken minute, is that a one-minute note costs **1.4–2.8 ETB**. That is roughly one to two US cents at the ~161 ETB/USD rate implied by Addis AI's own pricing ([Addis AI TTS benchmark](https://addisassistant.com/benchmarks/addis-voice-2-amharic)), so 100 notes a day costs 140–280 ETB. Cost is not the constraint; the one-job-per-wallet rule is. A backend serving many brokers must queue Scribe calls or negotiate Enterprise "dedicated throughput" through sales@addisassistant.com ([Docs: Rate Limits](https://docs.addisassistant.com/docs/platform/limits)).

## Default terms let Addis AI train on clients' voice notes

The Terms and Privacy Policy both took effect on 13 July 2026. They state that content submitted to the standard services "is not automatically private or confidential" and that **audio, transcripts and outputs may be used to train and improve models**. Restricted or no-training terms require a **written enterprise agreement** ([Privacy Policy](https://addisassistant.com/privacy); [Terms](https://addisassistant.com/terms)). The data collected includes recordings and voice characteristics that "may be biometric," and it is kept "for as long as stored in your account or needed." Processing can happen in **Ethiopia, Switzerland, the EEA** and wherever providers operate. Named subprocessors include Supabase, Cloudflare, PostHog and Sentry, alongside unnamed "AI, model, audio, and annotation providers" ([Privacy Policy](https://addisassistant.com/privacy)). Deletion "may not be immediate," and de-identified or aggregated data can survive account deletion ([Terms](https://addisassistant.com/terms)).

The commercial terms are friendlier. Paid API customers may build outputs into their own products, Addis AI assigns them its rights in output generated for them, and **no attribution is required**. Reselling the service as a standalone offering is not allowed. Ethiopian law governs the contract, liability is capped at the greater of 12 months' fees or **CHF 100**, and the service is provided "as is" with **no SLA** ([Terms](https://addisassistant.com/terms)).

For SmartBroker, a broker's dictation ("call Abebe on 0911…, 4.5 million birr, Bole") is personal data about third parties. Sending it to Scribe on standard terms means disclosing the training use in SmartBroker's own privacy notice, collecting explicit consent, and ideally negotiating a no-training agreement before cloud becomes the default. Ethiopia's own data-protection rules on sending client audio abroad were not researched and need a legal check. On-device transcription avoids all of this, which makes "offline preferred" a privacy decision as much as a connectivity one.

## Addis Scribe measures 20–28% WER, not the advertised 3%

Addis AI publishes three incompatible accuracy figures. The homepage claims **"3% WER"** ([addisassistant.com](https://addisassistant.com/)). The docs say the recording guidelines exist "to ensure high accuracy (WER < 10%)," with no test set or method ([docs: Speech-to-Text](https://docs.addisassistant.com/docs/capabilities/speech-to-text)). The only measured numbers are on Addis AI's own Scribe Streaming model card: **28.4% WER / 13.1% CER on 100 natural-speech WAXAL clips, and 19.8–20.6% WER / 7.7–8.2% CER on read FLEURS speech** ([HF: buctl mirror](https://huggingface.co/buctl/addis-scribe-streaming)). Its benchmarks page lists only a TTS study ([Addis AI Benchmarks](https://addisassistant.com/benchmarks)), and the independent GSMA EthioTelecomBench of 12 Amharic recognisers does not include Addis AI ([GSMAEthioTelecomBench](https://huggingface.co/datasets/SaarAI/GSMAEthioTelecomBench)).

Plan around the measured figures, not the 3%. They are less bleak than they look. Amharic words are long and agglutinative, so WER runs about three times CER ([Gete et al. 2025](https://arxiv.org/pdf/2503.18485)). A 28% WER therefore means roughly one character in eight is wrong: transcripts are readable but need checking. Addis AI's headline claim is that Scribe Streaming beats **Google Chirp 3 on WAXAL (28.4% vs 32.5% WER)** and on latency (first words in 1.56 s vs 6.67 s) ([t.me/addisassistantai/224](https://t.me/addisassistantai/224?embed=1)). Addis AI ran that test itself, and no one has reproduced it.

Against open alternatives, Addis AI is competitive rather than dominant. Off-the-shelf Whisper is unusable on Amharic. The strongest commercially usable open results come from the Ethio-ASR fine-tunes and Meta's Omnilingual ASR, and Omnilingual's only phone-ready build is also its weakest.

The bigger problem is that broker notes are made of exactly what benchmarks avoid: numbers, names and code-switching. Ethio-ASR **removes numerals before scoring** and the telecom benchmark **spells them out**. In Addis AI's own TTS study, numeric prompts scored **14.94% CER versus 4.44%** for ordinary text ([Ethio-ASR paper](https://arxiv.org/html/2603.23654); [GSMAEthioTelecomBench](https://huggingface.co/datasets/SaarAI/GSMAEthioTelecomBench); [Addis AI TTS benchmark](https://addisassistant.com/benchmarks/addis-voice-2-amharic)). Addis AI warns that heavy English code-switching and rare jargon reduce accuracy ([docs: Speech-to-Text](https://docs.addisassistant.com/docs/capabilities/speech-to-text)). A 2026 study of naturally occurring code-switched African speech found no system below 24% WER on any language ([AfriSwitch](https://arxiv.org/abs/2608.26434)). Errors will concentrate in prices, phone numbers, neighbourhood names and English loanwords, and no published benchmark measures those. Addis Scribe may well be the strongest Amharic recogniser on the market, but nothing yet shows it is better on broker speech. SmartBroker has to test it on its own audio.

## Android rules shape the integration more than the model does

Two Android constraints fix the product's shape before any model is chosen. First, SmartBroker cannot record the call itself. Google Play has blocked third-party call recording through the Accessibility API since **11 May 2022**, and microphone-based call recording was eliminated in Android 10 ([Engadget](https://www.engadget.com/google-is-banning-third-party-call-recording-apps-from-the-play-store-093201443.html)). The feature must therefore be **post-call dictation by the broker**.

Second, apps targeting Android 14+ cannot *create* a microphone foreground service from the background, and holding SYSTEM_ALERT_WINDOW is **not** one of the exemptions ([Android FGS background-start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start); [Android FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types)). flutter_overlay_window runs its UI in a separate Flutter entrypoint under a `specialUse` service ([pub.dev flutter_overlay_window](https://pub.dev/packages/flutter_overlay_window)). The overlay's mic button should therefore open SmartBroker's note screen, or a translucent dictation activity, and record from there. If dictation must survive a screen lock, start a microphone-type service while that activity is still visible, and test the flow on Android 14, 15 and 16. The existing Kotlin call-detection service should keep detecting calls and showing the overlay, nothing more.

Android's built-in recogniser is not a shortcut either. Google added online Amharic voice typing in 2017 ([Google blog](https://blog.google/products/search/type-less-talk-more/)), but the `amharic_stt` Flutter wrapper reports that offline Amharic needs a language pack "most devices lack" ([pub.dev amharic_stt](https://pub.dev/packages/amharic_stt)).

For capture, **record 7.1.1** (BSD-3) writes 16 kHz mono WAV with `RecordConfig(encoder: AudioEncoder.wav, sampleRate: 16000, numChannels: 1)` or streams PCM16 ([pub.dev record](https://pub.dev/packages/record)). At about 32 KB/s, a three-minute note is about 5.8 MB, well under Scribe's 25 MB cap.

For inference there are two credible Flutter engines. **whisper_ggml 2.7.1** is MIT-licensed, was released in October 2026 and bundles whisper.cpp 1.9.1. It needs Flutter 3.29+ and Dart 3.7+, so it works with 3.41. It runs any local ggml model file via `modelPath:`, supports a Silero VAD model and can keep the model loaded between notes ([pub.dev whisper_ggml](https://pub.dev/packages/whisper_ggml)). **sherpa_onnx 1.13.8** (Apache-2.0, September 2026) runs Whisper, NeMo CTC and transducer models, and Omnilingual CTC from one runtime with built-in VAD ([pub.dev sherpa_onnx](https://pub.dev/packages/sherpa_onnx)). Neither of the older packages belongs in a commercial app: whisper_flutter_new is GPL-3.0 and has not been updated since June 2024, and vosk_flutter has not been updated since April 2023 and has no Amharic model ([pub.dev whisper_flutter_new](https://pub.dev/packages/whisper_flutter_new); [pub.dev vosk_flutter](https://pub.dev/packages/vosk_flutter)).

Model conversion decides which engine goes first. whisper.cpp's `convert-h5-to-ggml.py` exists specifically to "convert Hugging Face fine-tuned models to ggml format," and its `quantize` tool shrinks the result to Q5_0 or Q8_0 ([convert-h5-to-ggml.py](https://raw.githubusercontent.com/ggml-org/whisper.cpp/master/models/convert-h5-to-ggml.py); [whisper.cpp README](https://raw.githubusercontent.com/ggml-org/whisper.cpp/master/README.md)). That gives Shook Tiny a documented path into whisper_ggml. sherpa-onnx's Whisper exporter expects OpenAI-format checkpoints, so a Hugging Face fine-tune must be remapped first. Its NeMo exporter covers CTC models but not the hybrid RNNT+CTC design that Addis Scribe uses ([sherpa-onnx Whisper export](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/whisper/export-onnx.html); [sherpa-onnx NeMo CTC export](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-ctc/nemo/how-to-export.html)). One detail still needs checking: whisper_ggml documents `modelPath:` for live sessions, and its file-transcription call should be confirmed to accept it too.

Size and speed favour a tiny-class model on the mid- and low-end phones common in Ethiopia. whisper.cpp needs about **273 MB of RAM for tiny, 388 MB for base and 852 MB for small** before quantization ([whisper.cpp README](https://raw.githubusercontent.com/ggml-org/whisper.cpp/master/README.md)). One developer measured whisper-base Q5_K at about 0.6× real time on a Pixel 6a's CPU ([dev.to](https://dev.to/software_mvp-factory/wiring-whispercpp-to-androids-audiorecord-api-hjo)). Extrapolating from that, a quantized Shook Tiny should transcribe a three-minute note in roughly half a minute to a minute and a half on a mid-range phone, and perhaps twice as long on a budget Helio or Unisoc device. That is an estimate, because no Amharic on-device benchmark exists. The Omnilingual int8 build (365 MB) and the Scribe GGUF (720 MB) are heavier downloads and riskier on 3 GB phones.

Google Play allows a 500 MB base module and 1.5 GB asset packs ([Play Console size limits](https://support.google.com/googleplay/android-developer/answer/9859372)). Even so, downloading the model on first use with **background_downloader 9.6.4** keeps the install small and lets the model update without an app release. Use user-initiated transfers and save to `applicationSupport` ([pub.dev background_downloader](https://pub.dev/packages/background_downloader)). The package has no checksum support, so check the file's SHA-256 against a manifest you host before moving it into place. Whisper-family models work in 30-second windows and Omnilingual accepts clips under 40 s ([HF sherpa-onnx Omnilingual card](https://huggingface.co/csukuangfj/sherpa-onnx-omnilingual-asr-1600-languages-300M-ctc-int8-2025-11-12)). Longer notes therefore need splitting with voice activity detection (VAD), which also cuts compute by passing only speech to the model ([whisper.cpp README](https://raw.githubusercontent.com/ggml-org/whisper.cpp/master/README.md)). Inference must run in a background isolate so the UI does not freeze.

## A four-phase plan delivers offline notes in about a month

The recommendation is to **integrate Addis AI in two ways at once and wait for neither**.

**One pipeline for every note.** Each note is first saved as a 16 kHz WAV file plus a row in a sqflite `transcription_jobs` table (note ID, audio path, engine, status, attempts, Scribe request ID). A `TranscriptionEngine` interface hides whether the text came from the phone or the cloud.

**On-device by default.** Use Addis AI's **Shook Tiny** through whisper_ggml, because it is the only Addis model built for phones with a licence that allows redistribution.

**Cloud as an option.** Offer **Addis Scribe** behind a backend proxy as an explicit, consented "improve with cloud" choice, and as the fallback when the on-device model is not installed.

**The official mobile model is a future upgrade, not a dependency.** Swap it in behind the engine interface when it is released.

**Brokers confirm the details.** Every transcript lands as an editable draft with the audio one tap away and numbers highlighted. It then passes through SmartBroker's existing AI Review LLM step, which turns spoken numbers into digits, and the broker confirms prices and phone numbers before they reach the CRM record.

The plan has explicit fallbacks. If Shook Tiny fails the test but Addis Scribe passes, ship store-and-forward cloud transcription under explicit consent and push for a no-training agreement: capture still works offline, and the text arrives when the phone reconnects. If Omnilingual CTC-300M beats Shook Tiny on SmartBroker's audio, switch the default engine to sherpa_onnx at the cost of a 365 MB download. If nothing meets the bar, the transcript still serves as a searchable draft next to the audio, which beats an untranscribed recording. My estimate of 12–20 developer-days in total assumes the ggml conversion works first time. It grows if Amharic output degrades after quantization or if fine-tuning becomes necessary.

## Conclusion

The key finding is not that Addis AI's offline model is missing. It is that SmartBroker's main quality risk does not depend on which vendor wins. Every Amharic recogniser available, Addis AI's included, makes enough errors that a wrong digit in a price or phone number is routine, and the published benchmarks deliberately leave numbers out of their scores. That makes quality a workflow problem as much as a model problem. Keeping the audio, highlighting names and numbers, and having the broker confirm them matters more than a few points of WER. A test set of real broker notes will be worth more than any vendor claim.

The engine interface also turns Addis AI's fast pace from a risk into an option. The company has shipped six SDK releases in under three months, shipped a new open model and an on-device demo in a single week, and says it is shifting toward small edge models. Meanwhile, its standard terms and one-job-per-wallet limit make the cloud a poor default for a CRM that handles client data. A SmartBroker that already transcribes offline with Shook Tiny can adopt the official mobile model the week it appears. As an early local customer, it is also well placed to ask Addis AI for the no-training terms and clear licensing that its public documents do not yet offer.
